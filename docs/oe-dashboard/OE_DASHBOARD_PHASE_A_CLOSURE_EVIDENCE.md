## Item 1 — trace_id Format Mismatch Investigation

### Root Cause (Confirmed)

| System | ID Field | Format | Generated By |
|--------|----------|--------|--------------|
| `options_pipeline_jobs` | `trace_id` | 16-char hex (e.g. `1e13a3d06db72a71`) | `hashlib.sha256(f"{ticker}{scan_date}{claim_id}".encode()).hexdigest()[:16]` — `aiem_options_scheduler.py` line 833 |
| `oe_decision_audit` | `decision_id` | 24-char hex | DPL system (`aiem_options_pipeline.py`), generated independently |

The two IDs have **different formats, different generators, and are never exchanged**. This is not a bug — they are architecturally separate namespaces.

### Schema Gap Confirmed

`oe_decision_audit` has no `ticker`, `scan_date`, or `alert_id` columns at the top level — those fields exist only inside JSONB blobs that are NULL for most prod rows.

`d3_governance_event_links.decision_id` is NULL for all 3,058 prod governance events (all are `D3_CHECKPOINT_MODE_CHANGE` mode events with no decision linkage).

### Working Join Path

```
options_pipeline_jobs.alert_id → aiem_options_alerts.id  (integer, confirmed live)
oe_options_metrics.trace_id    → options_pipeline_jobs.trace_id  (16-char hex, confirmed live)
oe_trade_records.trace_id      → options_pipeline_jobs.trace_id  (16-char hex, confirmed live)
oe_indicator_snapshots.trace_id → options_pipeline_jobs.trace_id  (16-char hex, confirmed live)
```

### Gap: `options_pipeline_jobs → oe_decision_audit`

This join **cannot be built** without a schema migration adding `scheduler_trace_id VARCHAR(16)` to `oe_decision_audit`.

**Dashboard treatment:** The lineage panel shows pipeline job → metrics → trade records (fully joinable). The `oe_decision_audit` link is shown as a grayed-out "Not linked — schema gap" badge. No forced join.
