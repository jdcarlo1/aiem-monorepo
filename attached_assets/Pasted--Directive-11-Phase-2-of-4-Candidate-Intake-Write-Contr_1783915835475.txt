## Purpose
Phase 1 added the status field. Phase 2 defines and enforces the write contract — the rules for who is allowed to write which status transitions — before any polling job or claiming logic exists. This prevents Phase 3 from being built against an ambiguous or unenforced contract.

## Required Design

1. **Enumerate every legal status transition explicitly:**
   - `PENDING_FULL_ANALYSIS` → `CLAIMED_BY_DIAGRAM1`
   - `CLAIMED_BY_DIAGRAM1` → `FULL_ANALYSIS_RUNNING`
   - `FULL_ANALYSIS_RUNNING` → `FULL_ANALYSIS_COMPLETED`
   - `FULL_ANALYSIS_RUNNING` → `FAILED`
   - `FAILED` → `RETRY_PENDING`
   - `RETRY_PENDING` → `PENDING_FULL_ANALYSIS` (requeue) or → `QUARANTINED` (after max retries)

   Any transition not on this list must be **rejected at the write layer**, not just by convention.

2. `_aiem_paper_pick_candidates()` may **ONLY ever** write the initial `PENDING_FULL_ANALYSIS` row. It must be structurally prevented (not just documented) from writing any other status value or calling any function that would.

3. **Define which component owns each transition:**
   - `PENDING_FULL_ANALYSIS`: written only by `_aiem_paper_pick_candidates()`.
   - All subsequent transitions: written only by `Diagram1CandidateIntake` (built in Phase 3) — this phase should stub or document the ownership boundary, not implement the intake job itself.

4. Add a DB-level or application-level constraint (CHECK constraint, trigger, or equivalent guard function) that rejects any write attempting an illegal transition, and prove it rejects at least one illegal transition attempt in this phase's evidence.

5. **No polling job, no atomic claiming, no `run_full_cycle()` invocation in this phase** — that is Phase 3.

## Deliverables for This Phase

1. A documented transition table (as code comments or a schema doc) listing every legal transition and its owning component.
2. An enforced guard (constraint/trigger/application check) rejecting illegal transitions.
3. Evidence that `_aiem_paper_pick_candidates()` cannot write any status other than `PENDING_FULL_ANALYSIS` — attempt an illegal write in a test/dev context and show it rejected (see Data Immutability Rule below for how to do this safely).
4. Confirm no existing candidate-selection behavior changed except the added guard.
