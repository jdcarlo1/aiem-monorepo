# PHASE 1 — DATA FOUNDATION
Source: AIEM_OPTIONS_AUTONOMY_MASTER_DIRECTIVE.txt §1, §3
Target: aiem_strat_scheduler.py, aiem_strat_engine/config.py, universe scan module
Scope: Options Engine only. Paper trading only. Do not touch D1/D2/D3.

## Requirements
1. Replace ticker-first LIMIT universe query with the point-in-time latest-row
   ranking query (§1 exact SQL). Do not assign direction from gap_pct/close_strength
   alone — that stays the signal engine's job (Phase 2).
2. Every module status must resolve to one of: AVAILABLE | STALE | MISSING |
   FAILED | NOT_APPLICABLE. Remove every silent 0.5-default fallback wherever
   it currently exists in the strat engine.
3. Mandatory component missing/stale/failed => INSUFFICIENT_DATA + NO_TRADE.
   Optional component unavailable => exclude + renormalize remaining weights
   (show the renormalization formula and one live example).
4. Log exception, module, ticker, trace_id, source timestamp on every failure.

## Evidence required (master §14 items 1, 2, 8)
- Item 1: raw SQL + full result set proving the new ranking query returns
  latest-row-per-ticker (not stale/duplicate rows), ordered rvol DESC, |gap_pct| DESC.
- Item 2: a real or forced stale-data case, raw log/DB proof it blocks with
  INSUFFICIENT_DATA rather than silently defaulting.
- Item 8: grep proof no `0.5` neutral-default literal remains as a fallback
  anywhere in the changed files (with any legitimate non-fallback 0.5 explained).
