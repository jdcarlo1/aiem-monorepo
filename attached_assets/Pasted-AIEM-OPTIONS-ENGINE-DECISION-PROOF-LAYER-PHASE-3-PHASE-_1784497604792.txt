AIEM OPTIONS ENGINE — DECISION PROOF LAYER PHASE 3
PHASE 2: INSTITUTIONAL AUDIT, INTEGRITY, AND GOVERNANCE HARDENING

PREREQUISITE: PHASE 1 MUST PASS
OBJECTIVE: Add stronger cryptographic integrity, independent approval, replay governance, database immutability, and durable institutional evidence.

====================================================

1. IMPLEMENT THE ENGINE INTEGRITY GATE
    ====================================================

Implement a live gate protecting:

* compute_req6_score
* _REQ6_SCORING_WEIGHTS
* All decision-affecting dependencies

Use a versioned canonical engine manifest and compute one root integrity hash.

The manifest should include:

* Scoring function AST hash
* Weight hash
* Imported helper hashes
* Configuration hashes
* Model artifact hashes
* Feature schema hash
* Python version
* Dependency versions
* Runtime flags
* Integrity schema version

Suppress decisions when the live root hash differs from the approved root hash.

Required negative controls:

* Change a scoring weight.
* Change scoring logic.
* Change a helper function.
* Change configuration.
* Change a model artifact.

Every change must cause the gate to block.

====================================================
2. DEFINE CANONICAL SERIALIZATION

Document and enforce:

* AST normalization method
* ast.dump parameters
* JSON encoding
* sort_keys=True
* separators=(”,”, “:”)
* ensure_ascii=False
* allow_nan=False
* UTF-8 encoding
* Component separator
* Canonicalization version
* Python version

The same approved state must always produce the same hash.

====================================================
3. PROTECT THE APPROVED HASH

The same automated process must not be able to modify both the engine and its approved reference.

Required:

* Independent authenticated approver.
* Protected pull-request approval, signed commit, or cryptographic signature.
* Read-only production reference.
* Exact commit SHA.
* Exact engine root hash.
* Approval timestamp.
* Approver identity.
* Signature or protected review evidence.

A free-form approved_by field is insufficient.

====================================================
4. IMPLEMENT NON-SELF-APPROVAL

Prove that the approver is different from:

* The code-producing agent.
* The deployment identity.
* The runtime process.

Reject:

* Missing approval.
* Forged approval.
* Mismatched commit.
* Mismatched root hash.
* Self-issued approval.
* Invalid signature.

====================================================
5. IMPLEMENT C27 END-TO-END REPLAY GOVERNANCE

Create oe_unreplayable_rows or equivalent.

For every non-test VERIFIED decision:

* Replay successfully, or
* Have an approved and verifiable exemption.

An exemption must include:

* Decision ID
* Reason code
* Exception class
* Evidence SEQ
* Archived log SHA-256
* Git commit
* Input hash
* Scorer or engine root hash
* Database identity
* Timestamp
* Approver identity

Missing or invalid evidence must FAIL.

Unexpected replay exceptions must FAIL.
