# Directive 7 — NVDA Candidate Selection vs. run_full_cycle Investigation

## Context

Prior audit work (Phase 8 Participation Audit, Stat Arb Sunday Retest Audit, NVDA Loop Participation Audit) established the following, confirmed via raw SQL:

- `aiem_diagram2_trace_audit WHERE ticker='NVDA'` returns **0 rows**. Diagram 1's `run_full_cycle('NVDA')` has never executed.
- Everything that looked like a live NVDA signal (GARCH, VPIN, Hurst, Bipower, VRP, PCA, Absorption Ratio, Regime) actually came from `_run_layer9_bg_scan`, a separate background job running every 2 hours via APScheduler, writing to `layer9_scores` — NOT the real orchestrator loop.
- Of the 39 quantitative indicators audited: only #38 (Relative Strength) is DIRECT into `ensemble_combiner`; 20 are INDIRECT (reach `signal_context` in principle, but most have never produced a real NVDA value); 18 are NOT IN Phase 8 at all.
- Confirmed broken: #20 OOS Testing has a hard schema bug (`aiem_signal_discoveries.created_at` column missing, blocks Stage 9 edge-filter evidence collection). #06 Thompson Sampling / #24 Bayesian Statistics are confirmed completely inert (wins=0, losses=0, zero adaptation, for any ticker).

**The open question, unresolved:** if `run_full_cycle('NVDA')` never ran, how did `_aiem_paper_pick_candidates()` select NVDA as a candidate? Does it call `run_full_cycle` and silently fail, or does candidate selection use a different/earlier code path entirely?

This is a separate track from the D3 governance rollout (Directive 6) — do not conflate the two.
