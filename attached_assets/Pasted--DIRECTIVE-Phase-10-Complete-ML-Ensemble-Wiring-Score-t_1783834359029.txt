## Problem Statement (from prior audit, verified via grep + live run)

1. `deep_rl`, `momentum_model`, `gaussian_process`, `online_learning`, and `alpha_model`
   return `score=None` in `_h_ensemble_combiner` because their output dicts don't contain
   the exact keys `"score"`, `"probability"`, or `"combined_score"` — only `rvol_signal`,
   `layer9_statistical_edge`, `meta_trust_signal`, and `specialist_council` pass the filter.

2. `packet.ensemble["combined"]` (the aggregate ML score) is written once at
   `aiem_master_orchestrator.py:1155` and never read again anywhere in the file —
   confirmed via:
   ```
   awk 'NR>=1173' aiem_master_orchestrator.py | grep -n "packet\.ensemble"
   ```
   which returns empty.

3. `_h_specialist_council` does NOT consume the ensemble combiner's output — it
   independently recomputes a verdict from `packet.debate`.

4. `_h_final_decision` gates trades only on `macro_ok`, `kill_ok`, `loss_ok`, `errors_ok`
   — it never reads any conviction/combined score.

## Required Fixes

### 1. Diagnose each non-contributing model individually
For `deep_rl`, `momentum_model`, `gaussian_process`, `online_learning`, `alpha_model`:
paste the actual dict keys each one returns (via raw print/log output, not description).
Identify the real key name holding the predictive value in each case.

### 2. Fix the key-matching logic
Fix `_h_ensemble_combiner` so it captures the real output key from each model, instead
of only accepting `"score"/"probability"/"combined_score"`. Do not just add more
accepted key names blindly — confirm each mapping is semantically correct (e.g. don't
accidentally pull a confidence interval bound instead of a point estimate).

### 3. Wire `packet.ensemble["combined"]` into the decision path
Either:
- (a) pass it into `_h_specialist_council` as an input the council actually weighs
  alongside its own debate-based verdict, and/or
- (b) add it as an explicit gate/input in `_h_final_decision` alongside the existing
  safety checks

State which approach was chosen and why.

### 4. Reconcile the two scoring systems
The inline orchestrator council and the canonical `specialist_council.run_council()`
currently diverge. State explicitly whether the canonical version is being deprecated,
merged, or left as dead code — don't leave two live, disagreeing implementations
without an explanation.
