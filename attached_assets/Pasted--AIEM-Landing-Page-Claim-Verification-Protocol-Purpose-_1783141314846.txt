# AIEM Landing Page Claim Verification Protocol
**Purpose:** Independently verify all 24 landing-page claims before public subscriptions open. No claim is accepted on the agent's word — only on raw, pasted, falsifiable output.

---

## GROUND RULES FOR THE AGENT (paste this section to it verbatim)

1. For every item below, run the exact commands specified (or reasonable equivalents if a filename/tool differs) and **paste the raw terminal output, SQL result set, or API response** into your reply. Do not summarize, paraphrase, or describe what the output "would show."
2. Do not mark anything ✅ **Live** yourself. Instead label each item **EVIDENCE ATTACHED** or **COULD NOT PRODUCE EVIDENCE**. Joel will make the pass/fail call from the raw output.
3. If a function exists but is not called anywhere in the live pick-generation path, that is a **FAIL**, not a "Live — see below." Dead code that merely exists is not a shipped feature.
4. If a value is identical across multiple tickers, multiple time periods, or multiple runs, treat that as a red flag and say so — do not explain it away.
5. Anything marked "just wired today" gets **extra scrutiny** (see flagged items below) — brand-new code has zero track record and is the most likely place for a stub, placeholder, or silently-failing call.
6. No interpretive language like "this confirms," "this proves," "working as intended." State only what the output literally shows.
