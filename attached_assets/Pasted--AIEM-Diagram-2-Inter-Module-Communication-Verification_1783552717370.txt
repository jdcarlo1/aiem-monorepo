## 7. LEARNING LOOP

Outcome Tracker → Attribution → Learning Systems → Memory → Master Orchestrator

- [ ] `grep -n` for each of the 4 hops showing the call site chain, in order.
- [ ] Confirm this is a closed loop back into the orchestrator (not a dead-end write to a table nobody reads). Show where the orchestrator actually reads from Memory before/during a new decision (file+line).
- [ ] Live proof: take one closed (completed) trade. Show:
  - the Outcome Tracker row for it (raw DB row)
  - the Attribution row derived from it (raw DB row)
  - the Learning Systems update it triggered (raw DB row or diff, e.g. trust weight before→after — same format as the `learning_update_applied` events already seen: `trust: X→Y`)

  - confirm (with file+line + a subsequent trace) that the NEXT decision cycle actually read this updated memory/weight before making its next pick. This last part is the one that actually proves the loop closes — a write with no confirmed downstream read is not a closed loop.
