## Item 1 — `paper_trade_id` write-back is not wired (Directive 11 Phase 3 dependency)

**Observed:** `paper_trade_id` is NULL in all rows of `aiem_candidate_pipeline`, including the 7 rows from today's FAP run. The candidate pipeline transitions to `FULL_ANALYSIS_COMPLETED` but is never linked back to the resulting row in `aiem_paper_trades`.

**Why this matters:** Without this link, there is no way to trace a given candidate back to the trade it produced (or vice versa). This directly affects Directive 11 Phase 3's atomic claiming/status lifecycle — a candidate can reach a terminal status without the system being able to prove which trade, if any, resulted from it.

**Required work:**
1. Grep for every write path into `aiem_paper_trades` and confirm whether `candidate_id` (or equivalent) is available at insert time.
2. Identify the specific code location where the write-back to `aiem_candidate_pipeline.paper_trade_id` should occur but currently does not.
3. Propose the fix (do not implement without confirming scope first — this may intersect with Phase 3 claiming logic already drafted).
4. State explicitly whether this is a missing line of code, a missing join key, or an architectural gap requiring more than a one-line fix.
