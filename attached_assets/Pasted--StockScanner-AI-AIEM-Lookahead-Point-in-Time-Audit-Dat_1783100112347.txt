## ❌ CONFIRMED ISSUE (needs your verification — may already be fixed)

### Survivorship / selection bias in universe construction — 9 backtest files

**The problem:** These files call `fetch_finviz_universe()`, which hits Finviz's screener **live, right now**, to build the ticker universe — then backtest that universe against a **historical** date range (e.g. `start="2026-04-01", end="2026-06-21"`). This means the backtest only ever tests tickers that *currently* pass today's nano-cap/float/price/volume filters. Any ticker that got delisted, reverse-split, or moved outside that filter range during the test window is silently excluded. This inflates win rate/Sharpe by an unknown amount — the classic "backtest looks great, live account doesn't" failure mode.

**Files affected (as of this snapshot):**
- `backtest_combo60.py`
- `backtest_deeper.py`
- `backtest_falsenegatives.py`
- `backtest_highfactor.py`
- `backtest_losers.py`
- `backtest_newrates.py`
- `backtest_quant_vs_v2.py`
- `backtest_rescued.py`
- `backtest_tiers.py`

**What "fixed" looks like:** universe is reconstructed *as of each historical date* using point-in-time float/price/volume (ideally via `point_in_time_guard.py` / the new `daily_fundamentals_snapshot` table now that it's accumulating history), not today's Finviz snapshot applied backward.

**How to re-verify with Replit Agent — ask for raw output, not a summary:**
```bash
grep -rn "fetch_finviz_universe" *.py
```
For each hit, confirm the universe-building call is scoped to a historical `as_of_date` (or reads from `daily_fundamentals_snapshot` filtered to dates <= the backtest window), not a live `requests.get("https://finviz.com/screener.ashx...")` call applied to a past date range. If Agent claims it's fixed, ask it to paste the actual current function body — not a description of the fix.
