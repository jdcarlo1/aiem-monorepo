2. REPAIR THE TREE=CLEAN CONTROL

The current exclusions are too broad and can hide unauthorized changes.

Prohibited behavior

Do not use this rule:

grep -v '^??'

It suppresses every untracked file, including possible Python code, shell scripts, SQL migrations, configuration files, secrets-handling files, or verification bypasses.

Do not blindly exclude:

dpl/engine_integrity_refs.json

This is a security-sensitive approval artifact containing hashes and commit information. Changing it must be visible and independently authorized.

Required implementation

Replace exclusion-based cleanliness with an explicit allowlist.

At minimum:

set -euo pipefail
ALLOWED_RUNTIME_PATHS=(
  "tools/verified_run_seq"
)
git status --porcelain=v1 -z > /tmp/git_status.bin
python3 tools/check_clean_tree.py \
  --status-file /tmp/git_status.bin \
  --allow-exact "tools/verified_run_seq"

check_clean_tree.py must:

1. Parse NUL-delimited Git status safely.
2. Fail on every tracked modification except explicitly permitted runtime-state files.
3. Fail on every untracked executable or code/configuration file.
4. Allow only exact known generated evidence paths.
5. Reject path traversal, renamed files, symlinks, directories, wildcard exclusions, and prefix matches.
6. Print every detected path and its classification.
7. Produce a SHA-256 digest of the complete status input.
8. Record the allowlist and status digest in the sealed run header.

Allowed untracked evidence should be written only into a dedicated generated-artifact directory with a strict filename schema and content hash. Prefer creating the log after the pre-run cleanliness check rather than ignoring arbitrary untracked files.
