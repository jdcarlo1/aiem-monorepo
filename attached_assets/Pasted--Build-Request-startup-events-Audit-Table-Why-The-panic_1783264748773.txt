# Build Request: startup_events Audit Table

## Why
The panic exhaustion scheduler registration currently only proves itself via a print() to a log file. That log has already caused two unverifiable/retracted claims this session because it doesn't survive process restarts or log rotation. This table replaces that with a permanent, queryable record.

## What to build

1. Create the table (if not exists):

```sql
CREATE TABLE IF NOT EXISTS startup_events (
    id          BIGSERIAL PRIMARY KEY,
    event_time  TIMESTAMPTZ DEFAULT NOW(),
    pid         INTEGER,
    git_sha     TEXT,
    event_key   TEXT,   -- e.g. 'panic_exhaustion_scheduled'
    detail      TEXT
);
```

Wire this creation into the same deferred-init pattern used for `aiem_panic_exhaustion_log` (i.e. add it to `_DEFERRED_INITS`, don't just define it and hope something calls it).

2. At the exact point where `print("[panic_exhaustion] daily 4:30 PM ET check scheduled")` currently fires, insert one row into `startup_events` with:
   - `pid` = current process ID
   - `git_sha` = current git SHA at boot (same value already used in the STALENESS-GUARD log line)
   - `event_key` = `'panic_exhaustion_scheduled'`
   - `detail` = whatever context is useful (e.g. the CronTrigger schedule string)

3. Do the same for the scheduler error path (the `except Exception as _e_pe_sched` branch) — insert a row with `event_key = 'panic_exhaustion_scheduler_error'` and the exception text in `detail`, so failures are just as durable as successes.
