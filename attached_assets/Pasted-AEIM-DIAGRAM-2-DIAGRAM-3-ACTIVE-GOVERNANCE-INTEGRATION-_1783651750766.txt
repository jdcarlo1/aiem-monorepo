MASTER IMPLEMENTATION AND STRICT VERIFICATION ORDER

IMPORTANT PURPOSE

Diagram 2 remains the sole trading-analysis and trading-decision pipeline.

Diagram 3 must NOT become a second stock-selection engine and must NOT independently modify ticker scores, technical indicators, probability outputs, council conclusions, or trade direction.

Diagram 3 is the active system-governance authority responsible for:

1. Architectural integrity.
2. Approved model/strategy/configuration versions.
3. System-wide safety and health.
4. Learning and promotion governance.
5. Audit integrity.
6. Controlled pause, quarantine, rollback, and recovery.
7. Authorization of system-level execution readiness.

The existing implementation is not complete because Diagram 3 is currently advisory-only and wired only to the Diagram 2 trade-close event.

Do not report Diagram 3 as fully integrated until all mandatory work and verification below passes.

==================================================
SECTION 1 — DEFINE PATH A AND PATH B
==================================================

PATH A — OBSERVATION / EVENT PATH

Diagram 2 publishes canonical, immutable lifecycle events to Diagram 3.

Diagram 3 records, validates, links, audits, measures, and reports these events.

Path A does not alter an ordinary Diagram 2 stock decision.

PATH B — ACTIVE ENFORCEMENT PATH

At designated mandatory checkpoints, Diagram 2 must synchronously request a governance authorization from Diagram 3.

Diagram 2 must technically obey the returned result.

Allowed results:

ALLOW
ALLOW_WITH_WARNING
REVIEW_REQUIRED
BLOCK
PAUSE_SYSTEM
QUARANTINE_COMPONENT
ROLLBACK_REQUIRED

For mandatory checkpoints:

ALLOW and ALLOW_WITH_WARNING may continue.

REVIEW_REQUIRED, BLOCK, PAUSE_SYSTEM, QUARANTINE_COMPONENT, and ROLLBACK_REQUIRED must prevent the protected action from continuing.

Path B is therefore the missing enforcement route.

SECTION 2 — DIAGRAM 3 AUTHORITY BOUNDARIES
==================================================

Diagram 3 MAY:

1. Observe and record all major Diagram 2 lifecycle events.
2. Raise warnings.
3. Require review of model, strategy, configuration, registry, and architecture changes.
4. Reject a model or learning proposal.
5. Block use of an unapproved model or strategy version.
6. Block execution when system-level integrity requirements fail.
7. Pause new trading activity during critical incidents.
8. Quarantine a module, tool, model, strategy, or configuration version.
9. Initiate a controlled rollback to a previously approved version.
10. Require human approval for high-impact changes.
11. Authorize recovery and resumption after verification.
12. Generate immutable executive, security, architecture, and performance records.

Diagram 3 MUST NOT:

1. Select stocks.
2. Re-score a stock.
3. Change BUY/SELL/HOLD based on an independent market opinion.
4. replace the Diagram 2 risk gate.
5. Bypass any Diagram 2 phase.
6. Directly execute a broker order.
7. Directly rewrite production code.
8. Silently change thresholds.
9. Deploy a learning/model change without approval evidence.
10. Modify or delete historical governance evidence.
