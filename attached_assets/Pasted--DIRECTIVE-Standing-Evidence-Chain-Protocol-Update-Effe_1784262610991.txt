## 2. New Rule — Validator Self-Check

Before any `verify_chain.sh` output is accepted as satisfying a directive, the agent must first run:

```
sha256sum tools/verified_run.sh tools/verify_chain.sh
```

and paste the raw output alongside the chain-verification output. This is checked against the canonical hashes in Section 1. **A mismatch means the validator itself has drifted and its output is rejected, regardless of what the chain log says.**

This is a check on the *tooling*, not on whether commands were genuinely run against real data — that still requires periodic independent spot-checks.

## 3. Full Requirement for Any Evidence-Chain Invocation Going Forward

1. **Validator self-check** (raw paste): `sha256sum tools/verified_run.sh tools/verify_chain.sh` — confirm both hashes match Section 1.
2. **Run the command through `tools/verified_run.sh`** (not `.local/`).
3. **Paste raw `tools/verify_chain.sh` output** against the resulting log.

This supplements — does not replace — the existing standing verification block (raw terminal output, before/after diffs, before/after file hashes, raw SQL where applicable; narrative claims without pasted evidence are rejected).
