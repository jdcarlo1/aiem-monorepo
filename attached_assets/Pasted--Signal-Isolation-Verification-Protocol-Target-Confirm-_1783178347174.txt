# Signal Isolation Verification Protocol
## Target: Confirm the 4 GEX/CTA signals are AIEM-only and only touch paper trades

**Rule: paste raw terminal/SQL output for every command below. No summaries, no "confirmed," no prose substitutes. If a command returns nothing, paste the empty result — don't describe it as empty.**

Signals in scope (all spellings/aliases):
`options_structure_scan`, `cta_trigger_scan`, `mkt_gex_scan`, `mkt_options_skew`,
`mkt_term_structure`, `mkt_cta_triggers`, `gex_m`, `gex_`, `pc_skew`, `term_ratio`,
`mkt_gex`, `mkt_cta`, `cta_score`, `l9_inst_struct`

### 1. Full-repo grep, not just frontend

Don't let the agent scope this to `.ts/.tsx` only — that's where it already claimed clean. Force it across the whole backend too.

```bash
grep -rn -E "options_structure_scan|cta_trigger_scan|mkt_gex_scan|mkt_options_skew|mkt_term_structure|mkt_cta_triggers|gex_m|pc_skew|term_ratio|mkt_gex|mkt_cta|cta_score|l9_inst_struct" \
  --include="*.ts" --include="*.tsx" --include="*.py" --include="*.js" \
  --exclude-dir=node_modules --exclude-dir=.git \
  . > /tmp/signal_grep_full.txt

wc -l /tmp/signal_grep_full.txt
cat /tmp/signal_grep_full.txt
```

Then have it categorize every single line into one of three buckets — no line gets dropped or waved off:
- AIEM tool maps / conviction reasoning (expected)
- Scheduler write jobs (expected)
- Anything else (**should be zero — if not zero, that's the finding, not something to explain away**)


### 3. Trace the actual write path into the two scan tables

```bash
grep -rn "INSERT INTO options_structure_scan\|INSERT INTO cta_trigger_scan\|options_structure_scan\.insert\|cta_trigger_scan\.insert" --include="*.py" . > /tmp/write_path.txt
cat /tmp/write_path.txt
```

This confirms only the scheduler jobs (8:38 AM / 10:05 AM ET) write to these tables — not some other job or endpoint.

### 4. Trace every READ from these two tables (this is the one that actually proves isolation)

```bash
grep -rn "FROM options_structure_scan\|FROM cta_trigger_scan\|SELECT.*options_structure_scan\|SELECT.*cta_trigger_scan" --include="*.py" . > /tmp/read_path.txt
cat /tmp/read_path.txt
```

Every result here should trace back to an AIEM tool function. If literally anything else reads these tables (a route handler, a different scoring module, a websocket push), that's a leak — full stop, not a caveat.

### 5. Confirm the paper trades table's write path only originates from AIEM decisions

```bash
cat /tmp/paper_trades_writes.txt
```

Check each write site — does it sit inside the AIEM decision/order-placement flow, or could paper trades be written from anywhere else?

### 6. Live DB check — actually query it, don't take code review as sufficient

```sql
-- Do any non-AIEM-tagged paper trades reference these signals in their reasoning/metadata?
SELECT id, symbol, reasoning, created_at
FROM paper_trades
WHERE reasoning ILIKE '%gex%' OR reasoning ILIKE '%cta%' OR reasoning ILIKE '%skew%'
ORDER BY created_at DESC
LIMIT 20;

-- Confirm row counts / freshness of the two scan tables match the two scheduled job times only
SELECT DATE_TRUNC('minute', created_at) AS ts, COUNT(*)
FROM options_structure_scan
GROUP BY 1
ORDER BY 1 DESC
LIMIT 20;

SELECT DATE_TRUNC('minute', created_at) AS ts, COUNT(*)
FROM cta_trigger_scan
GROUP BY 1
ORDER BY 1 DESC
LIMIT 20;
```

If any scan-table row has a `created_at` outside the two scheduled windows, that's evidence of an unauthorized write path — flag it.
