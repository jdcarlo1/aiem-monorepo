1. CHANGE THE ENGINE INTEGRITY GATE TO FAIL-CLOSED
====================================================

CURRENT PROBLEM

The integrity gate blocks a confirmed hash mismatch, but it may continue when:

- The integrity reference file is missing.
- The file is unreadable.
- The JSON is invalid.
- The verifier cannot import.
- An I/O error occurs.
- Hash calculation fails.
- An unexpected exception occurs.

This is not acceptable for an autonomous money-handling system.

REQUIRED PRODUCTION BEHAVIOR

- Verified exact match: ALLOW.
- Hash mismatch: BLOCK.
- Missing reference file: BLOCK.
- Invalid reference file: BLOCK.
- Import failure: BLOCK.
- File permission failure: BLOCK.
- I/O failure: BLOCK.
- Hash computation failure: BLOCK.
- Unknown verification exception: BLOCK.

When integrity cannot be verified, the engine may only:

- Monitor positions.
- Reconcile broker positions.
- Send alerts.
- Reduce risk.
- Close positions.
- Perform emergency liquidation.

It must not:

- Open new positions.
- Increase existing positions.
- Re-enter trades.
- Perform risk-increasing rolls.
- Create new autonomous order submissions.

IMPLEMENTATION REQUIREMENTS

- Add an explicit production environment check.
- Production must never skip the integrity gate.
- Development bypasses must be impossible in production.
- Store every block in oe_gate_events.
- Store trace_id, job_id, deployment commit, exception class, error details, expected hash, calculated hash and timestamp.
- Confirm no alert, decision approval or order intent is created after the gate blocks.

MANDATORY NEGATIVE CONTROLS

1. Delete the integrity reference file. Pipeline must block.
2. Corrupt the JSON. Pipeline must block.
3. Remove read permission. Pipeline must block.
4. Force verifier import failure. Pipeline must block.
5. Force hash-calculation exception. Pipeline must block.
6. Modify one protected component. Pipeline must block.
7. Confirm zero new-order intents after every blocked test.
