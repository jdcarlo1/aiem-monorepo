## 1. What is currently broken

`aiem_closed_loop_learning.py` correctly computes and stores `sampled_score` (a Beta(α,β) draw) per `signal_source` in `aiem_paper_thompson`. This value is written to audit tables and the governance dashboard.

It is **never read** by the candidate scoring path. The current multiplier chain in `_aiem_paper_pick_candidates()` is:

```
final_score = _raw_sc * _dm_lbl * _tw_lbl
```

- `_dm_lbl` = drift multiplier (from `drift_check_log.verdict`)
- `_tw_lbl` = trust multiplier (from `signal_trust_weights.trust_weight`, itself derived from `signal_trust_history` EMA — a *separate* win/loss tracker, not Thompson)

Thompson's `sampled_score` has no line of code that touches `final_score`, ranking, or go/no-go. The docstring at `aiem_closed_loop_learning.py:258` ("so pick_candidates can use it") is false and must be corrected regardless of outcome.

### 2.1 New read site

Inside `_aiem_paper_pick_candidates()`, **before** `final_score` is computed, add a fetch of the current Thompson score for the candidate's `signal_source`:

```python
# --- Thompson trust gate (Diagram 2 / decision layer) ---
_th_lbl = 1.0
try:
    _th_row = cu.execute(
        "SELECT sampled_score FROM aiem_paper_thompson WHERE signal_source=%s",
        (candidate_signal_source,)
    ).fetchone()
    if _th_row and _th_row[0] is not None:
        _th_score = float(_th_row[0])
        # map [0,1] sampled probability to a bounded multiplier band
        # keep the band conservative on first wiring pass — do not let
        # Thompson swing scores more than the existing trust multiplier does
        _th_lbl = 0.5 + _th_score  # range: 0.5x (score=0) to 1.5x (score=1)
    else:
        _th_lbl = 1.0  # no data yet for this source — neutral, not penalized
except Exception as _th_e:
    _th_lbl = 1.0
    logger.warning(f"[thompson-gate] fetch failed for {candidate_signal_source}: {_th_e}")
```
