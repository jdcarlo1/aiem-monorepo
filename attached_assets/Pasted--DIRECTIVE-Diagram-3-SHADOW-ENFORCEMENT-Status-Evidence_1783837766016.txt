## Context — the intended governance progression (do not treat this as a wiring bug)

The designed rollout for Diagram 3 is staged, not a single on/off switch:

```
SHADOW → VERIFIED SHADOW → PAPER ENFORCEMENT → FULL ENFORCEMENT
```

- In **SHADOW**, Diagram 3 receives real pipeline data and computes ALLOW/PAUSE/QUARANTINE/BLOCK verdicts, but the verdict cannot stop anything. This is correct and expected while validating that governance decisions are accurate and don't produce false blocks.
- **VERIFIED SHADOW** is the stage where a negative-control test (forcing a BLOCK and confirming it *would have* stopped execution, without actually enforcing) proves the mechanism works.
- **PAPER ENFORCEMENT** is where Diagram 3 can actually halt the paper Decision Engine on a BLOCK, without affecting live trading.
- Full enforcement follows once paper enforcement is validated.

The permanent target architecture is:

```
Diagram 3 produces governance verdict
        ↓
Diagram 1 validates and enforces it
        ↓
Diagram 2 acknowledges and obeys it
        ↓
Decision Engine may proceed only after approval
```

Diagram 3 should never directly modify stock scores, indicators, probabilities, or individual trade logic — enforcement, once live, flows through Diagram 1, not around it.

**The question this directive answers is not "should SHADOW mode be flipped to ENFORCEMENT" — it should not be, without passing the negative-control test first.** The question is: where in this progression is the system actually sitting today, with evidence, and has the negative-control test been run yet.
