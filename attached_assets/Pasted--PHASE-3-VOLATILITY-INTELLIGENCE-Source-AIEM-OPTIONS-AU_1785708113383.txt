# PHASE 3 — VOLATILITY INTELLIGENCE
Source: AIEM_OPTIONS_AUTONOMY_MASTER_DIRECTIVE.txt §5
Target: aiem_options_volatility_engine.py (create only if absent)
Depends on: Phase 2 CLOSED (SignalResult live)
Scope: Options Engine only. Paper trading only.

## Requirements
Calculate and persist: ATM IV, 52-week IV rank, IV percentile, realized
volatility, IV minus realized volatility, term structure, skew, expected
move, event IV expansion, estimated IV crush, volatility regime
(LOW|NORMAL|HIGH|EXTREME).

IV rank = (current_iv - rolling_low) / max(rolling_high - rolling_low, epsilon) * 100
IV percentile = percent of historical observations below current IV.

Never substitute "ATM IV > 40%" as a stand-in for IV rank — these are
distinct calculations and must both exist independently.

## Evidence required (master §14 items 6, 7, 12)
- Item 12: raw DB rows showing IV rank + IV percentile history for at least
  one real ticker across multiple sessions, with the rolling-window inputs
  shown (not just the output number).
- Item 6: one real high-IV-regime case and the downstream behavior it should
  trigger per §7's mapping (defined-risk credit/condor family) — behavior
  proof deferred to Phase 5, this phase only proves the regime classification
  itself is real and live-computed.
- Item 7: same, for a real low-IV-regime case.
- Claude will independently hand-check the IV rank/percentile formula against
  a known test case before accepting this phase (per standing quant-math rule).
