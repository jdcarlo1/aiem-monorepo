**Why the claim is inaccurate:** the test that validated this fix worked by *manually setting the halt state first*, then confirming Gate 7 reads it correctly. That proves the **read side** works. It does not prove the **write side** — i.e., it does not prove that a real 50% drawdown, occurring live, would ever get detected and written as a halt without the AIEM agent independently choosing to call `check_kill_switch()`. If the agent never calls that tool, no halt is ever written, Gate 7 has nothing to read, and it passes through regardless of actual account state — exactly the original gap, just one layer deeper now.

**How to fix this — concrete instruction:**

The fix needs to add a call to `check_kill_switch()` itself into the same structural, unconditional code path where `_is_currently_halted()` now lives — not just a check of the halt flag, but the evaluation that sets it. Specifically:

1. In `premarket_open_trader.py`, before or alongside Gate 7, add a call that runs the actual drawdown/loss evaluation unconditionally:
   ```python

           current_equity=_current_equity,

           limits=KillSwitchLimits(max_drawdown_pct=10.0)  # match existing config
   ```
