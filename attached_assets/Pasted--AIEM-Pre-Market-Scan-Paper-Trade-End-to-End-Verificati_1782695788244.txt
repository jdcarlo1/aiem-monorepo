# AIEM Pre-Market Scan → Paper Trade: End-to-End Verification Checklist

**Purpose:** Prove — with real executed output, not self-reported summaries —
that AIEM can autonomously scan pre-market, identify breakout candidates, and
record a paper trade through every required safety gate. Every item below
must produce a pasteable artifact (DB row, log line, JSON output) — not a
description of what *should* have happened.

**Ground rule for whoever runs this:** "It works" is not an acceptable answer
to any item below. Paste the actual output. If a step can't be completed,
say which one and why, instead of skipping to the next.

---

## 0. Pre-flight: confirm we are NOT touching real money

This is non-negotiable and must be verified FIRST, before any of the
functional tests below.

- [ ] Run `is_live_trading_enabled()` (from `simulation_lock.py`) and paste
      the literal return value.
      - Expected: `False`.
- [ ] Confirm `LIVE_TRADING_ENABLED` env var is either unset or `false`.
      Paste `echo $LIVE_TRADING_ENABLED` output.
- [ ] Confirm there is no broker order-placement integration wired into the
      scan→trade path (no Alpaca/IBKR/Schwab/TDA order calls). Grep the repo
      for `place_order`, `submit_order`, or any broker SDK import in the
      execution path and paste the (expected: empty) result.
- [ ] Call `simulation_lock_check` and paste its logged audit entry.

**If any of these come back showing live trading is possible, STOP — do not
proceed with the rest of this checklist. Report that immediately instead.**

## 3. Safety stack: every gate actually fires, not just exists

Run these IN ORDER, exactly as `main.py`'s documented safety order requires.
Paste output for each — a gate that always returns "pass" with no real check
is a rubber stamp, not a safety control.

- [ ] **`simulation_lock_check`** — paste result.
- [ ] **`is_eval_window_active`** — paste result. If `False`, this should
      stop the loop — confirm it actually does (don't let the agent proceed
      past a closed window).
- [ ] **`check_kill_switch`** — paste result including current
      `drawdown_pct`, `trades_today`, `consecutive_losses`.
      - [ ] Separately, artificially trip one limit (e.g. temporarily set
            `max_trades_per_day=1` and place two test paper trades) and paste
            the `halted: True` response plus the persisted `halted_reason` in
            `kill_switch_state`. Then run `clear_halt()` and paste that
            entry too. This proves the halt actually persists and actually
            blocks — not just that the function exists.
- [ ] **`regime_overlay_check`** — paste the 6-indicator output and whether
      it would block/reduce today.
- [ ] **`run_risk_gate`** — paste the full result for at least one real
      candidate: `gate_decision`, `reasons`, `devils_advocate` object,
      `cross_signal_agreement`. If `gate_decision` is `APPROVED` with an
      empty `reasons` list, sanity-check that this is genuinely a clean pass
      and not a misconfigured gate.
- [ ] **`gate_history`** (last 50) — paste the breakdown of
      APPROVED / APPROVED_WITH_CAUTION / BLOCKED counts. If BLOCKED+CAUTION
      is near zero, flag this explicitly — per the code's own comment, that
      means the gate isn't doing real work.
