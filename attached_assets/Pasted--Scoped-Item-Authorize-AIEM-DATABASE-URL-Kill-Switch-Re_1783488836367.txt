Authorized as its own scoped item, before starting `pre_decision_risk_gate` (Part 2 / Phase 11).

## Background

Item 7 follow-up confirmed the kill switch's fail-closed behavior is a real hard block (not a silent no-op): a missing `AIEM_DATABASE_URL` raises `RuntimeError` → caught → appended to `hard_blockers` → forces `decision = "skip"` → `write_paper_pick()` never reached. What it also surfaced: because `AIEM_DATABASE_URL` has never been set in this environment, the kill switch has never once reached its actual purpose — drawdown ceilings, loss-streak limits, trade-count limits. Every call has died at the connection step before that logic runs. It has been "safe" by accident of a missing config, not because the real limits were exercised and passed.
