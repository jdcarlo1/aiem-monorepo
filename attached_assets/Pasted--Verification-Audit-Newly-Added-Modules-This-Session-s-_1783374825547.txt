## Section A — Existence and import checks

```bash
for f in economic_calendar news_catalyst_monitor slippage_model \
         portfolio_correlation_risk historical_analog_search \
         niche_segment_finder daily_loss_limit self_coding_orchestrator \
         position_reconciler; do
  echo "=== $f.py ==="
  ls -la "${f}.py" 2>&1
  grep -n "^import ${f}\|^from ${f} import" main.py aiem_process.py 2>&1
  echo ""
done
```

For each file: confirm it exists on disk AND is actually imported somewhere
that runs at startup — a file existing with no import is dead code.

## Section B — AIEM tool registration (schema + tool map both required)

For modules 2, 4, 5, 6, 8, 9 (the ones with named AIEM tools), confirm the
tool appears in BOTH places — the earlier session already caught 7 tools
that were in `_tool_map` but missing from the schema list, silently
uncallable. Don't let that recur.

```bash
for tool in econ_is_high_impact_day estimate_options_slippage \
            check_portfolio_concentration mkt_find_historical_analogs \
            check_daily_loss_limit run_aiem_self_backtest; do
  echo "=== $tool ==="
  echo "-- in _tool_map:"
  grep -n "\"$tool\"" main.py | grep -i tool_map
  echo "-- in schema list:"
  grep -n "\"$tool\"" main.py | grep -i schema
  echo ""
done
```

Both greps must return a hit for each tool. Any tool with only one hit is
half-wired and uncallable by AIEM despite appearing to exist.

## Section C — Actual wiring into the decision path (not just tool existence)

A tool existing and being *callable by AIEM in chat* is different from it
being *automatically enforced* in the real paper-trade pipeline. Confirm
both, and be explicit about which is which for each module:

```bash
# Economic calendar hard gate — must be called INSIDE the paper-pick function,
# not just available as a standalone AIEM tool
grep -n -B5 -A15 "def.*paper_pick\|def.*generate_picks" main.py | grep -A15 "econ_is_high_impact_day\|economic_calendar"

# News catalyst filter — must run per-candidate inside paper-pick generation
grep -n -B5 -A15 "def.*paper_pick\|def.*generate_picks" main.py | grep -A15 "news_catalyst\|fda_rejection\|lawsuit\|sec_investigation"

# Slippage model — must be called before/inside actual order placement
grep -n -B5 -A15 "def.*place_order\|def.*submit_trade" main.py | grep -A15 "slippage_model\|estimate_options_slippage"

# Daily loss limit — must be checked before allowing new picks/orders
grep -n -B5 -A15 "def.*paper_pick\|def.*place_order" main.py | grep -A15 "daily_loss_limit\|check_daily_loss_limit"
```

**For each of the four checks above, report explicitly:**
- Is it wired automatically into the pipeline (runs without AIEM being asked)?
- Or is it only available as an AIEM tool AIEM must choose to call?
These are very different risk profiles and the answer must be stated plainly,
not implied.
