## PART 1 — CRITICAL BUG: Sizing gate is not enforced

### 1.1 Ground truth (already confirmed this session)
In the stage-16 risk_gate code path, `_pos_sizer.compute_position_size()` sets `gate_result`, but the consuming logic only does this:

```python
_sizing_gate = _sz.get("gate_result", "UNKNOWN")
if _sizing_gate == "APPROVED":
    _notional = _sz["calculated_notional"]
elif _sizing_gate not in ("PARAMS_NOT_CONFIRMED",):
    print(f"[aiem_paper] sizing gate {_sizing_gate} for {_t}: {_sz.get('gate_detail','')}")
```

There is no `continue` / `return` / `raise` on a non-APPROVED result. A `BLOCKED` gate only prints a warning — the trade still gets inserted, using a default $1000 notional. Trade #179's own row confirms this: `sizing_gate_result=NO_STOP_DEFINED`, and it still executed and closed.

### 1.2 Fix requirement
Add an actual block: any `gate_result` that is not `APPROVED` (and not the explicit bypass case `PARAMS_NOT_CONFIRMED`, if that bypass is intentional and Joel confirms it should stay) must skip trade insertion entirely — no default notional fallback.
