==================================================
SECTION 12 — AUTHORITATIVE DIAGRAM 2 ↔ DIAGRAM 3 WIRING MAP
==================================================

This section is mandatory.

No implementation may invent alternate direct connections.

All Diagram 2 ↔ Diagram 3 communication must use the canonical contracts defined below.

--------------------------------------------------
A. AUTHORITATIVE COMPONENT OWNERSHIP
--------------------------------------------------

DIAGRAM 2 OWNS:

1. Stock intake.
2. Data guards.
3. Macro and regime analysis.
4. Discovery.
5. Technical/options/quant analysis.
6. Probability engine.
7. Scoring and synthesis.
8. Specialist council.
9. Ordinary trade-risk gate.
10. Decision creation.
11. Paper/shadow/live execution request.
12. Outcome tracking.
13. Learning proposal creation.
14. Memory writes.

DIAGRAM 3 OWNS:

1. Architecture-baseline validation.
2. Approved version registries.
3. Governance system state.
4. Critical health and integrity policy.
5. Governance authorization.
6. Learning/model/strategy promotion approval.
7. Quarantine.
8. Pause.
9. Rollback.
10. Recovery and resume.
11. Governance audit and executive reporting.

DIAGRAM 3 DOES NOT OWN STOCK ANALYSIS.

DIAGRAM 2 DOES NOT OWN GOVERNANCE APPROVAL.

--------------------------------------------------
B. REQUIRED COMMUNICATION COMPONENTS
--------------------------------------------------

Create or identify exactly these canonical interfaces:

1. D2_EVENT_PUBLISHER
   Owned by Diagram 2.

   Responsibility:
   Publish immutable lifecycle events.

2. D3_EVENT_CONSUMER
   Owned by Diagram 3.

   Responsibility:
   Consume Diagram 2 lifecycle events and append them to the governance ledger.

3. D2_GOVERNANCE_CLIENT
   Owned by Diagram 2.

   Responsibility:
   Submit synchronous governance authorization requests at mandatory checkpoints.

4. D3_GOVERNANCE_SERVICE
   Owned by Diagram 3.

   Responsibility:
   Evaluate policy and return a typed governance decision.

5. D2_GOVERNANCE_ACKNOWLEDGER
   Owned by Diagram 2.

   Responsibility:
   Record whether Diagram 2 obeyed the Diagram 3 decision.

6. D3_GOVERNANCE_LEDGER
   Owned by Diagram 3.

   Responsibility:
   Store immutable events, requests, decisions, acknowledgements, state changes, and hashes.

No Diagram 2 module may write directly to Diagram 3 tables.

No Diagram 3 module may write directly to Diagram 2 decision or execution tables.

--------------------------------------------------
C. AUTHORITATIVE DATA FLOW
--------------------------------------------------

PATH A — ASYNCHRONOUS OBSERVATION FLOW

Diagram 2 phase
→ D2_EVENT_PUBLISHER
→ canonical communication bus
→ D3_EVENT_CONSUMER
→ schema validation
→ hash validation
→ D3_GOVERNANCE_LEDGER
→ health/performance/drift/reporting processors

PATH B — SYNCHRONOUS ENFORCEMENT FLOW

Diagram 2 protected checkpoint
→ D2_GOVERNANCE_CLIENT
→ D3_GOVERNANCE_SERVICE
→ policy evaluation
→ typed governance decision
→ D2_GOVERNANCE_CLIENT
→ Diagram 2 control flow
→ D2_GOVERNANCE_ACKNOWLEDGER
→ canonical communication bus
→ D3_GOVERNANCE_LEDGER

Diagram 2 must not continue a protected action until it receives a valid decision.

--------------------------------------------------
D. EXACT STAGE-TO-CHECKPOINT MAP
--------------------------------------------------

DIAGRAM 2 BOOT / SCHEDULER
contacts:
D3_GOVERNANCE_SERVICE at G0.

DIAGRAM 2 DATA-GUARD COMPLETION
publishes:
DATA_GUARDS_PASSED or DATA_GUARDS_FAILED.

contacts:
D3_GOVERNANCE_SERVICE at G1 only for system-wide integrity authorization.

DIAGRAM 2 PRE-DECISION ORCHESTRATOR
publishes:
REGIME_COMPLETED
DISCOVERY_COMPLETED
ANALYSIS_COMPLETED
PROBABILITY_COMPLETED
SYNTHESIS_COMPLETED
COUNCIL_COMPLETED.

contacts:
D3_GOVERNANCE_SERVICE at G2 before Decision Engine invocation.

DIAGRAM 2 RISK GATE
publishes:
RISK_GATE_PASSED or RISK_GATE_REJECTED.

Rules:
If rejected, stop.
Do not contact Diagram 3 to override a Diagram 2 rejection.

DIAGRAM 2 PRE-EXECUTION CONTROLLER
publishes:
DECISION_CREATED
EXECUTION_AUTHORIZATION_REQUESTED.

contacts:
D3_GOVERNANCE_SERVICE at G3.

Only after:
Diagram 2 risk gate == PASS
and
Diagram 3 decision == ALLOW or ALLOW_WITH_WARNING

may the execution adapter be called.

DIAGRAM 2 OUTCOME TRACKER
publishes:
EXECUTION_COMPLETED
OUTCOME_RECORDED.

Diagram 3 consumes these for performance, drift, health, and reporting.

DIAGRAM 2 LEARNING SYSTEM
publishes:
LEARNING_PROPOSED.

contacts:
D3_GOVERNANCE_SERVICE at G4.

No active model, strategy, threshold, registry, or configuration pointer may change before approval and acknowledgement.

DIAGRAM 2 RECOVERY ORCHESTRATOR
contacts:
D3_GOVERNANCE_SERVICE at G5.

No protected operation may resume without RESUME authorization.

--------------------------------------------------
G. NO-BYPASS ENFORCEMENT
--------------------------------------------------

Protected Diagram 2 code paths must not call the Decision Engine, execution simulator, live execution adapter, model activator, strategy activator, or resume controller unless a valid Diagram 3 decision exists.

Add explicit guards such as:

require_governance_authorization(checkpoint, trace_id)

The protected operation must be unreachable without the guard.

Static code inspection must prove no alternate bypass path exists.
