## Required fix before implementation: Guard B exception handling

Guard B's current design swallows all exceptions silently:

```python
except Exception:
    pass  # delivery failure must never affect lock release or return value
```

The *intent* is correct — a Telegram outage must never be able to affect the BLOCK path's behavior, lock release, or return value. Non-fatal is the right call. But silent is not. As written, if the Telegram alert fails, there will be zero record that an alert was even attempted, and a real BLOCKED_GO event could go unnoticed indefinitely.

**Fix:** log the exception without raising it or affecting control flow:

```python
except Exception as e:
    print(f"[Guard B] Telegram alert failed: {e}")  # non-fatal, but must be visible in logs
```

Same non-fatal guarantee, but now failure is visible instead of invisible.
