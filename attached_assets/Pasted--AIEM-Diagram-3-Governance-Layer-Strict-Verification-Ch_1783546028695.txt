**Standard:** Raw terminal output only. No narrative explanations, no "should work," no self-reports. Every item below requires a live-trigger test with pasted output, or it is not considered verified.

## 1. Forecast trend population (disclosure #1)

Claim: `/forecast` needs ≥2 health snapshots at different times to populate a trend, and will "self-populate automatically on the second health check cycle."

- [ ] Run `/forecast` now — paste raw response (expect error field).
- [ ] Trigger a health check cycle manually (provide the exact command/endpoint used).
- [ ] Wait for the second health check cycle to complete — paste the timestamp of each cycle.
- [ ] Run `/forecast` again — paste raw response.
- [ ] Confirm: does the trend field actually populate, or does it still error? If it errors, show the exact error and the DB row count for the health snapshot table at that moment.

**Not accepted:** "it will self-populate" as a statement. Only a before/after paste of two actual runs, with timestamps and DB row counts, counts.

## 2. open_trades consistency (disclosure #2)

- [ ] Trigger a staleness-guard restart mid-test and show the `open_trades` value immediately before and after the restart.
