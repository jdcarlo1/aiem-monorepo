# Finding: Stat Arb Pairs Engine — No Automated Retirement, Static Universe

**Table:** `stat_arb_pairs`
**Date verified:** 2026-07-11/12
**Severity:** Medium-High — active positions/signals can be built on structurally broken pairs indefinitely, with only a soft penalty rather than exclusion

---

## Summary

The stat arb (pairs trading) engine currently tracks exactly **3 hardcoded pairs**: XOM/CVX, JPM/BAC, META/GOOGL — all verified active against Polygon (real, common stock, not delisted). Two scheduled jobs run correctly:

| Job | Schedule | Purpose |
|---|---|---|
| `stat_arb_daily_scan` | Mon–Fri 9:10 AM ET | Computes daily z-scores off `polygon_market_daily` (pure SQL, no external API calls) |
| `stat_arb_weekly_retest` | Sunday 15:00 ET | Re-runs Engle-Granger cointegration tests on all `DEFAULT_PAIRS` |

Both are correctly wired and scheduled (confirmed via raw code at `main.py` lines 5894–5930).

**The structural problem is what happens *between* and *after* those retests.**

---

## Root cause: `is_active` is write-once-true, with no automated retirement path

- `stat_arb_engine.py` line 372: the upsert's `ON CONFLICT DO UPDATE` sets `is_active = TRUE` on every run, unconditionally.
- **There is no code path anywhere in the codebase that ever sets `is_active = FALSE`.** The only way a pair becomes inactive is a manual SQL statement (`UPDATE stat_arb_pairs SET is_active = FALSE WHERE ...`) run by hand.
- The weekly retest only updates cointegration statistics (`coint_pvalue`, `hedge_ratio`, `spread_mean`, `spread_std`, `last_tested`) — it does **not** touch `is_active`, even when a pair's p-value comes back showing the cointegration relationship has broken down.
- **Consequence:** a pair whose statistical relationship no longer holds remains `is_active = TRUE` forever, and continues to be picked up by every downstream consumer that filters on `WHERE is_active = TRUE` (confirmed at 8 separate call sites across `stat_arb_engine.py`, `daily_market_movers.py`, and `main.py`).

## Downstream impact: soft penalty, not hard exclusion

- `layer9_statistical_edge.py` and the Layer 9 score builder in `main.py` read `is_active` and `coint_pvalue`, but only apply a **penalty** if `coint_pvalue >= 0.15` — a broken pair is down-weighted, not excluded.
- Practical effect: a pair that has statistically failed can keep contributing to Layer 9 scores indefinitely, at reduced (not zero) weight, with no mechanism to ever fully retire it short of manual intervention.

## Pair universe is static

- All candidate pairs live in `DEFAULT_PAIRS`, hardcoded inside `stat_arb_engine.py`.
- There is no discovery process that proposes new candidate pairs — the universe has been fixed at 3 pairs (XOM/CVX, JPM/BAC, META/GOOGL) since inception, verified in the live `stat_arb_pairs` table (3 total rows, 3 active rows).

## Clarification on the META/GOOGL timestamp

- `last_tested = 2026-07-11 06:07:08 UTC` was initially flagged as close to the weekly retest window, but on inspection this is the **startup bootstrap run** (fires once at service start), not the scheduled Sunday 15:00 ET retest, which has not fired yet as of this check. Worth re-confirming after the next Sunday 15:00 ET run passes, to make sure the bootstrap run isn't masking whether the real scheduled retest is executing.
