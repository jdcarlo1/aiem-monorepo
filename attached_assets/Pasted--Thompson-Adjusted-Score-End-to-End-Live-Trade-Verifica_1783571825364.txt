# Thompson-Adjusted Score — End-to-End Live Trade Verification Directive

## Why this is being sent
Test C (audit trail) returned a synthetic row: `trace_id=th_verify_bda6ab2f`,
`ticker=VERIFY_C`, `paper_trade_id=None`. That proves the audit table CAN
store Thompson fields. It does NOT prove a real, executed paper trade
carries the Thompson-adjusted score through the full pipeline. `paper_trade_id: None`
is the disqualifying tell — fix that gap, don't explain it away.

## Standing rule
No self-reports. No "should work now." Every claim below must be answered
with raw terminal output, file+line numbers, or a SQL query result against
the live production DB. If a step can't be proven yet because the cron
hasn't fired, say so explicitly and state the next fire time — do not
simulate or backfill it.

## Step 1 — Trace the write path from gate to trade
Find and paste the exact code (file + line numbers) for:
1. Where `final_score` (post-Thompson-multiplier) exits `main.py`'s
   Learning Gate 3 block.
2. Where that same value is consumed by `aiem_paper_execute` (or whatever
   downstream module decides position/trade creation).
3. Where the Stage 14 `payload_json` (with `thompson_multiplier`,
   `thompson_sampled_score`, `thompson_signal_source`) gets written to
   `aiem_diagram2_trace_audit`.

Confirm in writing: is #3 written in the **same call/transaction** as the
trade that used #1's score? Or is it written by a separate, parallel
logging path that could drift from what was actually traded? If it's
separate, that's a second bug — fix it so the audit row is written from
the actual variable that produced the trade, not a recomputed copy.

## Step 2 — Wire `paper_trade_id` into the Thompson audit row
Right now `VERIFY_C` shows `paper_trade_id: None`. Identify why real gate
executions aren't attaching a trade id to the Stage 14 row. Likely causes:
- The audit write happens before the trade record is created (ordering bug)
- The audit write function was never passed the trade id as a parameter
- The audit write only fires on manual/test invocation paths, not the
  scheduled job

Fix so that any Stage 14 row generated by `aiem_paper_execute` running on
its schedule includes a non-null `paper_trade_id` matching the trade it
produced.

## Step 3 — Do NOT fake the cron run
The next legitimate market-hours execution window is the authoritative
test. Do not manually invoke `aiem_paper_execute` and call it proof — Test
B already showed manual invocation produces real gate math but that alone
doesn't validate the scheduled path. Wait for the actual cron fire.

## Step 4 — Required proof after the next scheduled run
Provide raw output for all of the following, in one message, timestamped:

1. **Cron log confirmation** — grep/log line showing `aiem_paper_execute`
   was invoked by the scheduler (not manually), with timestamp inside the
   market-hours window.
2. **Gate print lines** — the `[thompson-gate]` lines emitted during that
   run for whichever of the 7 tracked sources fired.
3. **SQL proof, non-synthetic**:
   ```sql
   SELECT trace_id, ticker, paper_trade_id, payload_json
   FROM aiem_diagram2_trace_audit
   WHERE stage_name = 'scoring_synthesis'
     AND started_at >= '<today's market-hours window start, UTC>'
   ORDER BY id DESC;
   ```
   Every row must have `paper_trade_id IS NOT NULL` and
   `payload_json` containing all three Thompson fields.
4. **Cross-reference the actual trade** —
   ```sql
   SELECT id, ticker, entry_score, thompson_multiplier_applied
   FROM aiem_paper_trades   -- or whatever the real trades table is called
   WHERE id = <paper_trade_id from step 3>;
   ```
   Confirm the score used to size/enter the trade equals the
   Thompson-adjusted `final_score` from the gate output, not the raw
   pre-multiplier score. If the trades table doesn't currently store
   `thompson_multiplier_applied` or equivalent, add the column and backfill
   the field going forward — otherwise there's no way to audit this later
   without re-deriving it from the JSON blob.
5. **One full ticker, traced top to bottom** — pick one ticker from that
   run and show: raw score → drift/trust weights → Thompson multiplier →
   final_score → the trade record it produced, with matching numbers at
   every hop.
