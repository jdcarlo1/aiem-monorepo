## Decision 2 — `conviction_stack` when 0 rows in table

**Rule:** Fail-closed. If `conviction_stack` generated a pick but `conviction_stack_watchlist` has 0 rows for that ticker (`MAX(snap_date)` returns NULL), treat as provenance-unknown — same category as `PRICE_PROVENANCE_UNKNOWN_DATE` in G6.

**Hard requirement — no free-text exception messages:**
- Must raise/log a distinct, structured, greppable error code (e.g. `CONVICTION_PROVENANCE_UNKNOWN_EMPTY_TABLE`), not a prose note buried in an exception message.
- Must be gated to dev/empty-table conditions through an explicit environment or state check — NOT just "table happens to be empty." An empty table in production from a real outage must NOT be waved off the same way.

**Required proof:**
- Show the exact code path where the dev-only condition is evaluated, and prove it cannot silently evaluate true in production (e.g. what breaks/fails loudly if this runs in prod with an empty table due to an outage).
- SQL query result showing `conviction_stack_watchlist` row count = 0 in dev, and the resulting error code being raised in a real run.
- Confirm no other code path can catch and suppress this error code without logging it.
