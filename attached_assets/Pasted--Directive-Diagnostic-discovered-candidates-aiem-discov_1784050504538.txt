## Item A — discovered_candidates has 0 rows despite 800 rows/day flowing in

`run_tiered_wl_cycle()` writes 800 rows/day to `daily_market_movers`
(confirmed working, CronTrigger mon-fri 17:10 ET). The discovery engine runs
20 minutes later. But `discovered_candidates` has 0 rows. Determine: is this
a legitimately strict filter (working as intended), or a logic bug (candidates
are being dropped somewhere they shouldn't be)?

### Required diagnostic steps

1. **Confirm current row count and full history**, not just "0 now":
   ```sql
   SELECT COUNT(*) AS total, MIN(created_at) AS earliest, MAX(created_at) AS latest
   FROM discovered_candidates;
   ```

2. **Trace the exact function(s) between `daily_market_movers` and
   `discovered_candidates`.** Grep for every function that reads from
   `daily_market_movers` and every function that writes to
   `discovered_candidates`. Paste raw grep output — do not paraphrase.

3. **Identify the filter logic** applied in that path (thresholds, conditions,
   any `WHERE` clauses or in-code filtering). Paste the actual filter
   conditions verbatim from the source.

4. **Run the filter logic manually against a sample of yesterday's 800 rows**
   from `daily_market_movers` and report how many would pass. If 0 pass,
   show the specific values that fail the filter and by how much (e.g.,
   "conviction score 0.31, threshold requires ≥0.60 — closest miss was 0.58").

5. **Determine verdict**: strict-filter-working-as-intended vs. logic bug.
   State which, and state the evidence that supports the determination —
   not a narrative conclusion alone.
