Use the existing system's tiers as-is:
- Nano: <$300M
- Small: $300M–$2B
- Mid: $2B–$10B

**Q2 — Market cap data source: Option A**
Polygon Fundamentals API via `POLYGON_API_KEY`. Batch call to
`/v3/reference/tickers` with market_cap filter, nightly backfill + daily refresh.

## Sample Trace Required After Implementation

Before declaring this feature complete, run one real ticker through the full
pipeline and paste the trail at every stage:

1. **Ticker selection** — which ticker was picked (pick one from each tier if
   possible, or at minimum one mid/small-cap that will actually flow through
   discovery), and the raw SQL that selected it.

2. **Market cap tier assignment** — raw market cap value pulled from Polygon,
   and which tier it landed in (Nano/Small/Mid/Large), with the actual
   comparison logic shown.

3. **Feature enrichment** — the full row (or JSONB blob) written to
   `feature_snapshot` for that ticker, showing which fields are populated and
   which are NULL, with the raw SQL SELECT confirming it's actually in the
   table.

4. **Candlestick pattern check** — raw output showing whether any pattern
   fired for that ticker's OHLCV that day, or confirmation none did.

5. **Discovery engine** — did this ticker generate a hypothesis/candidate?
   Show the raw row in `daily_market_movers` or `discovered_candidates`, or
   explain why it didn't qualify.

6. **Scheduler confirmation** — timestamp showing the 17:10 ET job actually
   fired and processed this ticker (not a projected/simulated time).

Every step needs raw output — table name, exact query, exact result. If the
ticker drops out at any stage (e.g., no candlestick pattern, doesn't clear a
threshold), that's fine — just show *why* with the actual data, not a summary
saying "processed successfully."
