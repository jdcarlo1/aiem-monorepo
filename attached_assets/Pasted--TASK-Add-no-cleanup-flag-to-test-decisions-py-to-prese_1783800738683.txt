# TASK: Add `--no-cleanup` flag to `test_decisions.py` to preserve DB evidence

## Problem

`test_decisions.py` inserts test rows into two tables, runs confirm queries against them, then deletes those rows in a cleanup step at the end. This means any "raw SQL output" captured from a run reflects a *reproduction*, not the original evidence — the rows are gone by the time anyone can independently inspect them.

## Required change

1. Add a command-line flag `--no-cleanup` (use `argparse` or `sys.argv` check, whichever matches the existing script's convention).
2. When `--no-cleanup` is passed, skip **every** `DELETE FROM` call at the end of the test run. Locate all cleanup `DELETE FROM` statements in the file and wrap them in a conditional so they only execute when the flag is *not* set.
3. Default behavior (no flag) must be unchanged — normal CI runs still clean up.
4. When `--no-cleanup` is used, print a clear line at the end of the run stating which tables/rows were left in place and the exact `WHERE` conditions needed to query them back out (e.g. ticker, test-run ID, timestamp) so they're independently queryable afterward.
5. Do not alter the insert logic, the confirm-query logic, or any of the 9 existing test cases (D1-A/B, D2-A/B/C, D3-A/B/C/D). This is scoped strictly to the cleanup step.

## Out of scope

Do not touch the contamination-rate threshold (5%) or add any new decision logic — that is a separate open item and is not part of this fix.
