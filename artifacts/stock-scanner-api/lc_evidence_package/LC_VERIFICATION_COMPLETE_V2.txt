  CSV:  lc_evidence_package/section_g.csv

  Query used:
    SELECT pt.id, pt.ticker, pt.trade_type, pt.status, pt.created_at,
           COUNT(l.id) AS leg_count
    FROM aiem_paper_trades pt
    JOIN ase_paper_trade_legs l ON l.paper_trade_id = pt.id::text
    GROUP BY pt.id, pt.ticker, pt.trade_type, pt.status, pt.created_at
    ORDER BY pt.created_at

  Result: 0 rows.
  Explanation: ase_paper_trade_legs stores string IDs of the form
  "ase_pt_<hex>" and legacy UUIDs. aiem_paper_trades uses integer IDs.
  The join produces 0 rows by design — the ASE leg table is a standalone
  child table referencing its own string-keyed parent, not the integer-keyed
  aiem_paper_trades table. This is the correct and expected behaviour.
